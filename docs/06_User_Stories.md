# E-Commerce System — User Stories

## 1. Purpose

This document defines user stories for the E-Commerce System. Each story describes a feature from the perspective of the user who needs it.

## 2. User Stories

| Story ID | User Story                                                                                                     | Priority |
| -------- | -------------------------------------------------------------------------------------------------------------- | -------- |
| US-01    | As a customer, I want to register an account so that I can access the e-commerce system.                       | High     |
| US-02    | As a registered customer, I want to log in securely so that I can access my account.                           | High     |
| US-03    | As a customer, I want to search for products so that I can find items quickly.                                 | High     |
| US-04    | As a customer, I want to view product details so that I can make informed purchasing decisions.                | High     |
| US-05    | As a customer, I want to add products to my shopping cart so that I can purchase selected items.               | High     |
| US-06    | As a customer, I want to update or remove cart items so that I can manage my purchase.                         | High     |
| US-07    | As a customer, I want to review my order total before checkout so that I understand the amount payable.        | High     |
| US-08    | As a customer, I want to provide delivery details so that my order can be delivered to the correct address.    | High     |
| US-09    | As a customer, I want to pay using an available payment method so that I can complete my purchase.             | High     |
| US-10    | As a customer, I want to receive an order confirmation so that I know my order has been placed.                | High     |

## 3. User Story Format

Each user story follows this structure:

**As a** [user role],
**I want** [a feature or capability],
**So that** [the benefit or business value].

### Example

**As a customer, I want to track my order so that I can check its current status.**

* User role: Customer
* Requirement: View order status
* Business value: Better visibility and customer experience

## 4. Prioritization

* **High:** Essential for the main shopping journey or core administration.
* **Medium:** Useful functionality that can be planned after the core features.

Priorities are preliminary and should be confirmed with business stakeholders.

## 5. Conclusion

These user stories translate business needs into user-focused requirements. They provide a foundation for defining acceptance criteria, prioritizing the product backlog, and planning Agile sprints.
